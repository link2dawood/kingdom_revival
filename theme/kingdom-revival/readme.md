=== Kingdom Revival Ministries ===
Requires at least: 6.6
Tested up to: 7.1
Requires PHP: 7.4
License: GPLv2 or later

Custom theme for kingdomrevivalministries.com, converted from the approved HTML design.

== Installing ==

1. Back up the site (database + wp-content). Nothing in this theme deletes content, but a backup is the safe first step on a live site.
2. Appearance → Themes → Add New → Upload Theme → choose kingdom-revival.zip → Install → Activate.
3. Open Kingdom Revival → Setup and click "Run setup". It:
   - imports the design's images and video into the Media Library (files already in the library are reused, not duplicated) and adds alt text where it is missing; photos that were not on the old site (the Outreach gallery, the upright Urdu Bible photo) and the old site's Elementor thumbnail crops (home page cards and photos, the home hero) are copied from assets/images/content/, so nothing is fetched from the old site's elementor/thumbs folder,
   - creates the 16 ministries of the client's sitemap in two groups (Gospel & Spiritual Ministries, Compassion & Humanitarian Ministries; "Youth Ministry / Women Empowerment" as a draft, hidden until the client decides), the 7 stories (filed under the "Blogs" category, plus an empty "Updates" category), and the pages About Us, Our Impact (with Testimonies and Photo & Video Gallery), News & Updates, Partner With Us (with Prayer Request), Contact and Donate (inc/data/pages.php),
   - moves WordPress's sample post "Hello world!" to the trash, if it was never edited (it would otherwise show in News & Updates),
   - creates the menus and assigns them to this theme's empty menu locations,
   - optionally sets the Reading settings (static front page + News & Updates as posts page) and /news/post-name/ permalinks (stories live under News & Updates) — only if you tick those boxes.
   Anything that already exists with the same slug or name is skipped and left unchanged, with one exception: on an existing ministry, Setup replaces only photo settings nobody has edited (a gallery that still shows just the placeholder photo, the old sideways Urdu Bible photo, and alt texts still set to the old one-phrase-per-ministry wording). You can run Setup again at any time.
4. Appearance → Customize → Site Identity: upload a logo (optional; the bundled logo is used otherwise, and it is already the church logo). Search engines get the bundled 512×512 logo (assets/images/krm-logo-large.png) unless you upload one. The header and footer show the bundled logo at 64, 128 or 192 pixels (krm-logo-64.png, krm-logo-128.png, krm-logo.png), whichever the screen needs; an uploaded logo is shown through its WordPress-made sizes, never the full upload (after uploading, a plugin such as Regenerate Thumbnails rebuilds the sizes of a logo uploaded before theme 1.8.0). Contact details, social links and impact numbers can be edited with live preview under Customize → Kingdom Revival.
5. Kingdom Revival → Settings: check the contact details, add social media links, the PayPal account email (enables secure one-time and monthly PayPal checkout, saved Donations and receipts — see "Online giving"), bank details and the email address that receives form notifications.
6. Install an SEO plugin: Rank Math or Yoast SEO (both free; SureRank, which the previous site used, also works). The plugin manages every page's SEO title, meta description, canonical URL, Open Graph and Twitter tags, schema and sitemap; the theme then prints none of these tags itself, so nothing is duplicated (for schema, see below). Where a page's field in the plugin is empty, the theme offers the design's title, description and hero image as the default; anything typed in the plugin wins. Rank Math only takes over once its setup wizard is completed or skipped. Tip: set the plugin's title separator to "|" so story and ministry titles match the design ("Baptisms | Kingdom Revival Ministries").
   Without an SEO plugin the theme prints basic tags itself.
   Structured data (schema): the SEO plugin's is kept and nothing is printed twice. The theme adds what the plugin does not build from the theme's fields: Event (an event with a start date and a venue or address) and VideoObject (a sermon whose video is embedded). With Yoast SEO and Rank Math it also adds the ministry's details (address, phone, email, logo, founder) where the plugin left them out, makes the breadcrumb match the one on the page, credits stories to the author box ("Kingdom Revival Ministries Team") instead of the WordPress user, and drops Rank Math's default "Article" on pages that aren't stories. Without an SEO plugin the theme prints all of it (Organization, WebSite, WebPage, BreadcrumbList, BlogPosting, Event, VideoObject).
   Kingdom Revival → Settings → Structured data: the organisation type (Organization, or NGO only if the ministry is a registered non-governmental organisation) and the city, province and country of the address. Set Settings → General → Timezone to Karachi so event times are given in Pakistan time.
   With Rank Math: Titles & Meta → Local SEO → choose "Organization" (it defaults to a person) and add the logo.
   Permalinks must be "Post name" (Settings → Permalinks); Setup can set this.
   Redirects from the previous site's addresses (e.g. /donate-us/ → /donate/, /baptisms/ → /what-we-do/baptisms-discipleship/; the addresses this theme renamed in 1.10.0, such as /ministries/… and /blog/, redirect automatically) are on by default: Kingdom Revival → Settings → Redirects.
7. Make sure the site can send email (an SMTP plugin is recommended on most hosts) so form notifications arrive. Every submission is also saved under Kingdom Revival → Submissions.
8. Online giving (PayPal), see "Online giving" below: enter the PayPal Business account email in Kingdom Revival → Settings → Online giving, test in Sandbox mode, then switch to Live.

== Editing content ==

Everything below is edited in the dashboard; no plugin is needed.

* Page text, headings, images and buttons: Pages → edit Home, About Us, Our Impact, Testimonies, Photo & Video Gallery, News & Updates, Partner With Us, Prayer Request, Contact or Donate. The "Page content" box has one section per part of the page (Hero, Who we are, FAQ…). Fields start with the design's content; lists (cards, photos, FAQ questions…) can be added to, removed and reordered. "Restore this section to the original design" undoes edits to a section.
  - Headings marked "formatting allowed" accept <em>…</em> for the highlighted words (on the home page: <span style="color: #F5A04A">…</span>).
  - Text can use {phone}, {email}, {address} and {year}; links can use {home}, {about}, {contact}, {donate}, {partner}, {blog}, {ministries} (What We Do page), {impact}, {testimonies}, {gallery}, {prayer}, {email}, {phone}, {whatsapp}, {paypal}, or #section.
  - Form fields (names, emails, topics…) and the "Where it is needed most" gift option are fixed, because the forms and donation page depend on them.
  - Text in [square brackets] is a placeholder waiting for the client's wording (PHASE-REPORTS.md, Phase 18, has the full list).
  - Placeholders and visitors: data-driven sections (impact counters, "Your gift at work" / "How your gift helps" cards, stories and testimonies, churches, camps / projects timelines, Projects, team and pastors) show their placeholders only to logged-in administrators, each such section with a small "Only administrators see this section" label. Visitors see only real entries: a counter, card, story or person that is still empty or a [placeholder] is left out on its own, and a section with none is not printed at all (no heading, no gap). The data file's sample projects are shown to administrators only. Beyond those sections, any text holding a [placeholder] is treated as empty for visitors (krm_public(); everything printed through the page content fields passes through it), so e.g. a "[District]" row in Where we work is left out, "[00] villages" counts are not shown, "Help free a family · [Amount]" reads "Help free a family", the About history, founder testimony and timeline appear only once written, and a Statement of Faith line opens as an accordion only once it has an explanation. Giving cards and the ministry donation card show raised / goal and the progress bar only once a goal is set (the Donate button always). Log out (or use a private window) to see the page as visitors do; tools/visual-qa/placeholder_check.js crawls the site and lists any placeholder a visitor could see. Developers: filter `krm_show_placeholders`.
  - Ministries waiting for their description (Persecuted Christian Support, Food Relief, Disaster Relief & Recovery Ministry, and Youth Ministry / Women Empowerment) are Drafts: they appear in no card, menu, filter or sitemap, and their address sends visitors to What We Do (302). Publish one (Ministries → edit → Publish) once its text is in, and it appears everywhere by itself.
  - Testimonies: while no Testimonial is published, the Testimonies page is left out of menus, links and sitemaps for visitors, and its address goes to Our Impact (302). The first published testimonial brings it back. Fields whose help says "DRAFT — CLIENT TO APPROVE" (and ministries showing that notice) hold proposed wording waiting for the client's sign-off.
  - Home → Hero and donation card → "ministry the gift goes to": the card's Donate button opens Donate with that ministry chosen (default Children & Orphan Care).
* Home page sections (Pages → Home → Page content), in page order: Hero and donation card, Your gift at work (amount cards), About, Ministry explorer, Giving cards, Flagship: Freedom from Slavery (five steps and the before/after photo slider; the step numbers 01–05 follow the list order), Flagship cards (Urdu Bibles, Church Planting), Where we work (places list; optional map image with pins placed by % from the left and top, the first pin is the red headquarters pin), Ministry in action (video and photos), Stories from the field (quotes; photo optional), Get involved, Prayer request, Founder (quote, WhatsApp button and "Read his story" link; leave a text empty to hide it), What we believe and our team (one belief per line; team photos), Latest news & blogs (the three newest posts, automatic), Closing verse, Floating WhatsApp button, Floating "Donate" panel.
  - Text in [square brackets] (amounts, names, villages, district counts, the founder's quote, team members, "[Amount]") is the design's placeholder: replace it with the real content before launch.
  - Prayer requests are saved under Kingdom Revival → Submissions ("Prayer request") and emailed to the form notification addresses, with the same spam protection as the contact form. WhatsApp links use the WhatsApp number in Kingdom Revival → Settings.
* Site text (Kingdom Revival → Site text): header name, top bar button, footer, ministry page and story page wording, the What We Do page (/what-we-do/: header image, headings, introduction, filter tab and card labels; its "Your gift at work", "Three Ways to Stand With Us" and closing verse sections are the home page's, edited in Pages → Home), the 404 page and the sermons/events/testimonials page headings.
* Ministries (dashboard → Ministries), the "What We Do" of the client's sitemap at /what-we-do/: title, Excerpt (the short description), focus, "how this ministry serves" points, extra sections ("## Heading", text, "- point" lines; Children & Orphan Care has "Sunday School"), "How your gift helps" cards ("amount | what it gives | text", one per line; up to 4; visitors see only cards with an amount; administrators see "[$ ]" placeholder cards up to 3), camps / projects completed ("date | location | people served" lines: a timeline, used by Medical & Health Outreach and Clean Water Projects), churches & house churches planted ("name | place | planted" lines: a list, used by Church Planting) — both not shown at all while empty — photo gallery, home page explorer image and position (0 = not in the explorer), and the What We Do card: label on the photo, card text (empty = the Excerpt), raised and goal in whole dollars (empty = "[Amount]" and an empty bar, as in the design) and impact stats ("value | label", one per line; shown on Our Impact and as 3–4 counters on the ministry page, "[00]" placeholders while empty).
  Every ministry page (/what-we-do/{slug}/) is the one template single-ministry.php with template-parts/ministry/*: hero (first photo, breadcrumb, the group as the small heading, title, Excerpt) · intro (the home About photo pair from the 2nd and 3rd photos, "What we do", the points, the focus) · impact counters · How your gift helps · up to 9 photos with the photo viewer (more: a link to the Gallery filtered to the ministry) · one testimony (the first Testimonial whose Related ministry is this one) · a donation card beside them that stays in view (the home card's amounts, the ministry's raised/goal bar; Donate opens with the ministry and amount chosen) · Slavery & Freedom Ministry only: the home page's five freedom steps and before/after slider (edited in Pages → Home → Flagship) · churches / camps when they have rows · three other ministries of the same group · the home page's closing verse. Wording shared by all ministry pages: Site text → Ministry pages, and → Ministry pages: side donation card. The Ministry Group box sets the filter tab and mega-menu column. Page Attributes → Order sets the order everywhere. To hide a ministry, save it as a Draft (Youth Ministry / Women Empowerment is one until the client decides). Every page reads ministries from one place (krm_ministries()); a field a ministry has never saved uses its entry in inc/data/ministries.php.
  Theme 1.10.0 moves an existing site once to the sitemap (inc/upgrade.php): ministries renamed (old addresses redirect), Children Ministry merged into Children & Orphan Care, the four new ministries added, the two groups, the new pages, Blogs/Updates categories, and new menus (the old menus are kept, renamed "… (before 1.10)"). Values someone has edited are left alone.
* Projects (dashboard → Projects): Donate → "Our Projects" (tabs Current / Upcoming) and the first three current ones on the home page. Title, Excerpt (card text), Featured image (else the ministry's photo), and in "Project details" the ministry, current or upcoming, goal, raised and planned date. "Give to this project" opens Donate with the ministry chosen; "Pledge / Get notified" opens the pledge form on Partner With Us with the project filled in. Until a project is published the placeholder projects of inc/data/projects.php show.
* Our Impact: all figures (headline counters, impact by ministry, growth, district table, families freed per year, financial allocation, annual report link) live in inc/data/impact.json; replace a null with the verified number. Visitors see each of those parts only once it has data (administrators see every part, marked "Only administrators see this section"); the Where we work map, Stories and the closing call to action always show. Donate's "Financial transparency" link jumps to "How donations are used" once a percentage is filled in, else it opens the page.
* Home page links: the hero card, gift cards, flagship cards, Freedom button and the ministry explorer's "Support this ministry" open Donate with their ministry chosen (/donate/?ministry={slug}#give); "See the churches" opens Church Planting's churches list; the stats bar links to Our Impact.
* About Us: the timeline, founder biography, statement-of-faith explanations, extra team members and the Registration & accountability section (Reg. No., board, partners) appear for visitors only once filled in; a belief without an explanation is a plain line, not an accordion. Testimonies (/our-impact/testimonies/) lists the Testimonials (Related ministry = its filter tab); /testimonials/ now leads there. Photo & Video Gallery (/our-impact/gallery/): every ministry's photos plus "General photos", and the YouTube links listed in that page's content box (they load only when played), filtered by ministry.
* Partner With Us: five ways to partner; Prayer Partners, Financial Partner (pledges), Church & Ministry Partners and Volunteer With Us each have a sign-up form (name, email or WhatsApp, country, church/organisation for church partners, message), saved under Kingdom Revival → Submissions ("Partner With Us sign-up") and emailed. Prayer Request (/partner-with-us/prayer-request/; /prayer-request/ redirects there) uses the home page's prayer form text, with extra fields: country, request type (Healing, Family, Salvation, Other) and "Keep my request private". Required fields show a message under the field; "Email or WhatsApp" accepts an email address or a phone number.
* Contact: five cards (Call, Email, Visit, WhatsApp, Office hours). The phone, email and address come from Kingdom Revival → Settings; the WhatsApp and Office hours card text is in Pages → Contact → Page content → Contact cards. Visitors see the Office hours card only once the hours are filled in (the other four then share the row). The "Follow the ministry" social block shows the Facebook / YouTube / Instagram links from Settings, and is hidden from visitors while none is set. The map shows the address in Page content → Map.
* Donate: every "Support this ministry" / ministry Donate button links to /donate/?ministry={slug}#give, which preselects that ministry ("Where most needed" for an unknown slug); ?for={name} still works. The trust row shows the Reg. No. from Pages → About Us → Page content → Accountability once it is filled in, and links to Our Impact's financial transparency section (/impact/ redirects to /our-impact/). The Stripe option is shown to administrators only until Stripe is connected.
* News & Updates (/news/): stories live at /news/{story}/ and the categories at /news/category/…; the old /{story}/ and /category/… addresses redirect there. The filter chips are the top-level categories (Blogs, Updates); add another top-level category in Posts → Categories and it becomes a chip. A story's own (topic) category stays its label.

== Online giving ==

Gifts are paid on PayPal's own secure pages (paypal.com): by PayPal balance or by debit/credit card without a PayPal account. No card details reach WordPress, and no API keys are stored. The Donate page looks and works as in the design; the gift form fills in PayPal's checkout.

* Kingdom Revival → Settings → Online giving:
  - PayPal account email: the ministry's PayPal Business account (it must be able to receive payments; PayPal does not open accounts for Pakistan, so it is held by the partner abroad). With it set, donors get PayPal's checkout for one-time AND monthly gifts with the amount and ministry filled in, and gifts are recorded. Empty = the PayPal.me link (one-time only, nothing recorded).
  - PayPal mode: Sandbox (testing on sandbox.paypal.com, no real money) or Live.
  - Thank-you receipts: on/off, plus the receipt email's subject and message (placeholders {name}, {full_name}, {amount}, {frequency}, {fund}, {date}, {transaction}, {email}, {phone}).
* How a gift is recorded: every checkout tells PayPal to report the payment to this site (PayPal "Instant Payment Notification", sent to /wp-admin/admin-post.php?action=krm_paypal_ipn). The theme sends each report back to PayPal to confirm it is genuine and that it is for the ministry's account; only then is it saved under Kingdom Revival → Donations (donor, email, amount, monthly or one-time, ministry, PayPal fee and transaction ID; Export CSV). The donor is emailed the thank-you receipt once the payment is Completed, and the ministry is notified at the form notification addresses. Repeated reports never create duplicates. Refunds, reversals and cancelled monthly gifts update the donation and notify the ministry.
* After paying, PayPal returns the donor to the Donate page's thank-you view (/donate/?thanks=1; not indexed by search engines). Its wording is in Pages → Donate → Page content → "Thank-you view".
* Testing: create a free PayPal Developer account (developer.paypal.com), use its sandbox Business account's email in Settings with mode Sandbox, and give from the sandbox Personal account. The site must be reachable from the internet for PayPal's reports to arrive (not localhost). Sandbox gifts are marked "sandbox test" in Donations. Switch to Live and enter the real account email before launch.
* Monthly gifts are PayPal subscriptions: donors can cancel them in their PayPal account; the ministry can see and cancel them in its PayPal account.

== Speed ==

The theme already loads only what each page needs: one or two small stylesheets, scripts at the end of the page, the self-hosted font (preloaded, shown with a fallback font until it arrives), lazy-loaded images below the first screen, and a high-priority preload of each page's large hero image. Run Setup's image import (step 3 above): after it, images come from the site's own Media Library in the right size for each screen (phones get smaller files) instead of full-size files from the old site. Kingdom Revival → Settings → Images → "Image format" saves those resized copies as WebP (the default; much smaller files at the same visible quality). Images already uploaded keep their current copies until rebuilt with a plugin such as Regenerate Thumbnails. The home page's background video plays only on screens 768px and wider, and not for visitors whose device asks for reduced motion or has data saver on: the HTML carries no video link or poster, assets/js/front.js adds them only in that case, so phones never download the video and keep the background photo (WebP, with its JPG original as the poster fallback). It starts once the page has finished loading and pauses while scrolled out of view. The default is the ministry's own hero video, shipped with the theme: a 15-second loop, 1280px wide, no sound, as assets/video/hero.mp4 (H.264, about 2.2 MB) and assets/video/hero.webm (VP9, about 3.1 MB) (Pages → Home → Page content → "Background video (MP4 link)" and "WebM version"; they show as "krm-theme:video/hero.mp4" / ".webm"). A replacement should be similar: short, silent, under 4 MB. The photo viewer (assets/js/viewer.js) loads only on pages with photos that open full screen: home, About, ministry pages, stories, sermons and events. Design images are looked up in the Media Library in one go per page (two queries instead of two per image). Ministry gallery photos load as they scroll into view, in the size the photo grid shows. Cards and gallery tiles (home cause cards and field stories, story cards, Donate's impact cards, ministry and story galleries, What We Do) get 4:3 crops of portrait photos (sizes krm-card-480/800/1200, made only for photos taller than 5:4), so phones no longer download a whole tall photo to show its middle band; the crop shows exactly what the card showed. Images uploaded before theme 1.8.1 get these crops in the background, a few at a time on WP-Cron (option krm_card_backfill, -1 when done). Standard-density desktops up to 1536 px wide get the 1536 px copy of a hero or band photo when it is big enough to cover it; sharper screens keep the full image. Kingdom Revival → Settings → Images → "Unused plugin styles" leaves out WordPress editor styles and the Dashicons font that some plugins add to every public page (visitors only; on by default).
Most of a slow PageSpeed score usually comes from plugins, not the theme: page builders (Elementor, Elementor Pro, Header Footer Elementor), starter-template and form plugins load their CSS, fonts and jQuery on every page although the theme does not use them. Keep only the plugins the site needs (see GO-LIVE-CHECKLIST.md in the project).

On the hosting side (a theme cannot set these):
* Page caching: use the host's page cache, or one caching plugin (e.g. WP Super Cache, W3 Total Cache or LiteSpeed Cache on LiteSpeed servers). Pages are cache-safe: visitors' pages carry no per-visitor data.
* Compression and browser caching for theme files and uploads. Theme files have a version in their address (?ver=…) that changes with every theme update, so they can be cached for a year. On Apache/LiteSpeed hosts without a caching plugin that does this, add to .htaccess:
    <IfModule mod_deflate.c>
      AddOutputFilterByType DEFLATE text/html text/css application/javascript application/json image/svg+xml
    </IfModule>
    <IfModule mod_expires.c>
      ExpiresActive On
      ExpiresByType text/css "access plus 1 year"
      ExpiresByType application/javascript "access plus 1 year"
      ExpiresByType font/woff2 "access plus 1 year"
      ExpiresByType image/webp "access plus 1 year"
      ExpiresByType image/jpeg "access plus 1 year"
      ExpiresByType image/png "access plus 1 year"
      ExpiresByType video/mp4 "access plus 1 year"
    </IfModule>
* Optimisation plugins: they are not needed for the theme's own files. Avoid "delay JavaScript until interaction" options (the menus, donation form and gallery would not respond to the first tap) and extra lazy-loading of images or backgrounds (it would delay the hero image, which the theme loads first on purpose).

== Security and accessibility ==

* Forms (contact, partner, newsletter, prayer request) are protected without a captcha: a hidden "leave empty" field, a signed token from the page the form is on (it does not expire, so cached pages keep working), a minimum time on the form, at most 5 messages per visitor per 10 minutes, and messages with more than 3 links are kept as "possible spam" without an email. Logged-in users' posts also need a WordPress nonce. "Please reload the page and try again" means the token was missing — usually a page cached before a theme update; clear the page cache.
* Submissions and Donations hold visitors' personal details: only Editors and Administrators can see or export them. Settings, Site text and Setup need an Administrator.
* Front-end pages send the headers X-Content-Type-Options, X-Frame-Options (SAMEORIGIN), Referrer-Policy and Permissions-Policy. If the host or a security plugin already sends them, remove the theme's with the `krm_security_headers` filter.
* Visitors can't look up user names (/?author=1 goes to the home page; the REST users list needs a login).
* Not done by the theme (use the host or one security plugin, e.g. Wordfence or Solid Security): login attempt limits, two-factor login, a firewall, XML-RPC blocking, file-change scans, backups.
* Accessibility: "Skip to content" link, keyboard-operable menus (Enter/Space opens, Esc closes), donation tabs (arrow keys), photo viewer and popups (focus stays inside, Esc closes, focus returns), visible focus outlines, labelled form fields whose errors are read out, alt text on every image (from the Media Library, or the alt field beside each image in Page content). When adding images, always fill in the Media Library "Alternative text"; leave it empty only for purely decorative images.

== Privacy ==

The font is served from the theme (no Google Fonts request). Form submissions are stored in WordPress and emailed to the ministry; nothing is sent to third parties unless a newsletter service URL is added in Settings. Donations: payment happens on PayPal's site under PayPal's privacy policy; the theme stores the donor name, email, country, amount and PayPal transaction ID that PayPal reports, never card details.
