Requires at least: 6.6
Tested up to: 7.1
Requires PHP: 7.4

Custom theme for kingdomrevivalministries.com, converted from the approved HTML design.

== Installing ==

1. Back up the site (database + wp-content). Nothing in this theme deletes content, but a backup is the safe first step on a live site.
2. Appearance → Themes → Add New → Upload Theme → choose kingdom-revival.zip → Install → Activate.
3. Open Kingdom Revival → Setup and click "Run setup". It:
   - imports the design's images and video into the Media Library (files already in the library are reused, not duplicated) and adds alt text where it is missing; photos that were not on the old site (the Outreach gallery, the upright Urdu Bible photo) and the old site's Elementor thumbnail crops (home page cards and photos, the home hero) are copied from assets/images/content/, so nothing is fetched from the old site's elementor/thumbs folder,
   - creates the 16 ministries of the client's sitemap in two groups (Gospel & Spiritual Ministries, Compassion & Humanitarian Ministries; "Youth Ministry / Women Empowerment" as a draft, hidden until the client decides), the 7 stories (filed under the "Blogs" category, plus an empty "Updates" category), and the pages About Us, Our Impact (with Testimonies and Photo & Video Gallery), News & Updates, Partner With Us (with Prayer Request), Contact and Donate (inc/data/pages.php),
   - moves WordPress's sample post "Hello world!" to the trash, if it was never edited (it would otherwise show in News & Updates),
   - creates the menus and assigns them to this theme's empty menu locations,
   - optionally sets the Reading settings (static front page + News & Updates as posts page) and /news/post-name/ permalinks (stories live under News & Updates) — only if you tick those boxes.
   Anything that already exists with the same slug or name is skipped and left unchanged, with one exception: on an existing ministry, Setup replaces only photo settings nobody has edited (a gallery that still shows just the placeholder photo, the old sideways Urdu Bible photo, and alt texts still set to the old one-phrase-per-ministry wording). You can run Setup again at any time.
4. Appearance → Customize → Site Identity: upload a logo (optional; the bundled logo is used otherwise, and it is already the church logo). Search engines get the bundled 512×512 logo (assets/images/krm-logo-large.png) unless you upload one. The header and footer show the bundled logo at 64, 128 or 192 pixels (krm-logo-64.png, krm-logo-128.png, krm-logo.png), whichever the screen needs; an uploaded logo is shown through its WordPress-made sizes, never the full upload (after uploading, a plugin such as Regenerate Thumbnails rebuilds the sizes of a logo uploaded before theme 1.8.0). Contact details, social links and impact numbers can be edited with live preview under Customize → Kingdom Revival.
5. Kingdom Revival → Settings: check the contact details, add social media links, the PayPal account email (enables secure one-time and monthly PayPal checkout, saved Donations and receipts — see "Online giving"), bank details and the email address that receives form notifications.
6. Install an SEO plugin: Rank Math or Yoast SEO (both free; SureRank, which the previous site used, also works). The plugin manages every page's SEO title, meta description, canonical URL, Open Graph and Twitter tags, schema and sitemap; the theme then prints none of these tags itself, so nothing is duplicated (for schema, see below). Where a page's field in the plugin is empty, the theme offers the design's title, description and hero image as the default; anything typed in the plugin wins. Rank Math only takes over once its setup wizard is completed or skipped. Tip: set the plugin's title separator to "|" so story and ministry titles match the design ("Baptisms | Kingdom Revival Ministries").
   Without an SEO plugin the theme prints basic tags itself.
   Structured data (schema): the SEO plugin's is kept and nothing is printed twice. The theme adds what the plugin does not build from the theme's fields: Event (an event with a start date and a venue or address) and VideoObject (a sermon whose video is embedded). With Yoast SEO and Rank Math it also adds the ministry's details (address, phone, email, logo, founder) where the plugin left them out, makes the breadcrumb match the one on the page, credits stories to the author box ("Kingdom Revival Ministries Team") instead of the WordPress user, and drops Rank Math's default "Article" on pages that aren't stories. Without an SEO plugin the theme prints all of it (Organization, WebSite, WebPage, BreadcrumbList, BlogPosting, Event, VideoObject).
   Kingdom Revival → Settings → Structured data: the organisation type (Organization, or NGO only if the ministry is a registered non-governmental organisation) and the city, province and country of the address. Set Settings → General → Timezone to Karachi so event times are given in Pakistan time.
   With Rank Math: Titles & Meta → Local SEO → choose "Organization" (it defaults to a person) and add the logo.
   Permalinks must be "Post name" (Settings → Permalinks); Setup can set this.
   Redirects from the previous site's addresses (e.g. /donate-us/ → /donate/, /baptisms/ → /what-we-do/baptisms-discipleship/; the addresses this theme renamed in 1.10.0, such as /ministries/… and /blog/, redirect automatically) are on by default: Kingdom Revival → Settings → Redirects.
7. Make sure the site can send email so form notifications arrive: add the SMTP constants to wp-config.php (see "Form emails" below) or use an SMTP plugin. Every submission is also saved under Kingdom Revival → Form Submissions.
8. Online giving (PayPal), see "Online giving" below: enter the PayPal Business account email in Kingdom Revival → Settings → Online giving, test in Sandbox mode, then switch to Live.

== Editing content ==

Everything below is edited in the dashboard; no plugin is needed.

* Page text, headings, images and buttons: Pages → edit Home, About Us, Our Impact, Testimonials, Photo & Video Gallery, News & Updates, Partner With Us, Prayer Request, Contact or Donate. The "Page content" box has one section per part of the page (Hero, Who we are, FAQ…). Fields start with the design's content; lists (cards, photos, FAQ questions…) can be added to, removed and reordered. "Restore this section to the original design" undoes edits to a section.
  - Headings marked "formatting allowed" accept <em>…</em> for the highlighted words (on the home page: <span style="color: #F5A04A">…</span>).
  - Text can use {phone}, {email}, {address} and {year}; links can use {home}, {about}, {contact}, {donate}, {partner}, {blog}, {ministries} (What We Do page), {impact}, {testimonies}, {gallery}, {prayer}, {email}, {phone}, {whatsapp}, {paypal}, or #section.
  - Form fields (names, emails, topics…) and the "Where it is needed most" gift option are fixed, because the forms and donation page depend on them.
  - Dummy content: every section that had no client content yet shows made-up content (names, numbers, amounts, quotes, testimonials, projects). The full list is in PHASE-REPORTS.md, "Dummy content instead of [placeholders]". Replace it all with real content before launch. Text in [square brackets] is still treated as a placeholder (administrators only) if you type it yourself.
  - Placeholders and visitors: data-driven sections (impact counters, "Your gift at work" / "How your gift helps" cards, stories and testimonies, churches, camps / projects timelines, Projects, team and pastors) show their placeholders only to logged-in administrators, each such section with a small "Only administrators see this section" label. Visitors see only real entries: a counter, card, story or person that is still empty or a [placeholder] is left out on its own, and a section with none is not printed at all (no heading, no gap). Until the first Project is published, everyone sees the data file's dummy projects (inc/data/projects.php). Beyond those sections, any text holding a [placeholder] is treated as empty for visitors (krm_public(); everything printed through the page content fields passes through it), so e.g. a "[District]" row in Where we work is left out, "[00] villages" counts are not shown, "Help free a family · [Amount]" reads "Help free a family", the About history, founder testimony and timeline appear only once written, and a Statement of Faith line opens as an accordion only once it has an explanation. Giving cards and the ministry donation card show raised / goal and the progress bar only once a goal is set (the Donate button always). Log out (or use a private window) to see the page as visitors do; tools/visual-qa/placeholder_check.js crawls the site and lists any placeholder a visitor could see. Developers: filter `krm_show_placeholders`.
  - Ministries waiting for their description (Persecuted Christian Support, Food Relief, Disaster Relief & Recovery Ministry, and Youth Ministry / Women Empowerment) are Drafts: they appear in no card, menu, count, Donate fund list or sitemap, and their address sends visitors to their group page (302). Publish one (Ministries → edit → Publish) once its text is in, and it appears everywhere by itself.
  - Testimonials (Our Impact → Testimonials, /our-impact/testimonies/; called "Testimonies" before theme 1.17.1) is always in the menu and the sitemap. It lists the published Testimonials (dashboard → Testimonials) with filter tabs by ministry. Theme 1.17.1 created the 12 DUMMY testimonials of inc/data/testimonials.php on sites that had none. Each data entry has `is_sample: true`; set it to `false` to hide that sample from public visitors while administrators keep seeing it for review. When no public testimonial remains, the empty message and "Share your testimony" form appear. Replace the samples with real, consented stories before launch; deleted samples are not recreated. Fields whose help says "DRAFT — CLIENT TO APPROVE" (and ministries showing that notice) hold proposed wording waiting for the client's sign-off.
  - Home → Hero and donation card → "ministry the gift goes to": the card's Donate button opens Donate with that ministry chosen (default Children & Orphan Care).

== Online giving ==

Gifts are paid on PayPal's own secure pages (paypal.com): by PayPal balance or by debit/credit card without a PayPal account. No card details reach WordPress, and no API keys are stored. The Donate page looks and works as in the design; the gift form fills in PayPal's checkout.

* Kingdom Revival → Settings → Online giving:
  - PayPal account email: the ministry's PayPal Business account (it must be able to receive payments; PayPal does not open accounts for Pakistan, so it is held by the partner abroad). With it set, donors get PayPal's checkout for one-time AND monthly gifts with the amount and ministry filled in, and gifts are recorded. Empty = the PayPal.me link (one-time only, nothing recorded).
  - PayPal mode: Sandbox (testing on sandbox.paypal.com, no real money) or Live.
  - Thank-you receipts: on/off, plus the receipt email's subject and message (placeholders {name}, {full_name}, {amount}, {frequency}, {fund}, {date}, {transaction}, {email}, {phone}).
* How a gift is recorded: every checkout tells PayPal to report the payment to this site (PayPal "Instant Payment Notification", sent to /wp-admin/admin-post.php?action=krm_paypal_ipn). The theme sends each report back to PayPal to confirm it is genuine and that it is for the ministry's account; only then is it saved under Kingdom Revival → Donations (donor, email, amount, monthly or one-time, ministry, PayPal fee and transaction ID; Export CSV). The donor is emailed the thank-you receipt once the payment is Completed, and the ministry is notified at the form notification addresses. Repeated reports never create duplicates. Refunds, reversals and cancelled monthly gifts update the donation and notify the ministry.
* After paying, PayPal returns the donor to the Donate page's thank-you view (/donate/?thanks=1; not indexed by search engines). Its wording is in Pages → Donate → Page content → "Thank-you view".
* Testing: create a free PayPal Developer account (developer.paypal.com), use its sandbox Business account's email in Settings with mode Sandbox, and give from the sandbox Personal account. The site must be reachable from the internet for PayPal's reports to arrive (not localhost). Sandbox gifts are marked "sandbox test" in Donations. Switch to Live and enter the real account email before launch.
* Monthly gifts are PayPal subscriptions: donors can cancel them in their PayPal account; the ministry can see and cancel them in its PayPal account.

== Light and dark mode, scroll effects ==

Light / dark mode
- Visitors switch with the sun/moon button in the header (on phones: the last row of the menu, "Dark mode"). Until they choose, the site follows the device's setting. The choice is remembered in the browser (localStorage "krm-theme") and applied before the page appears, so there is no flash of the other theme.
- Every colour is a token in assets/css/theme-global.css (":root" for light, the two dark blocks right after it for dark). Change a colour there, never in a template. Roles: --color-heading (navy text), --color-band (navy sections), --color-surface (cards, forms, header), --color-bg (page), --color-bg-soft (grey sections), --color-secondary-text (red text), --color-orange (pill buttons, always with dark --color-on-accent text). Photos are never recoloured.
- Logo: in dark mode, and over a photo at the top of a page, the header logo sits on a white round badge (as in the footer). If the client supplies a light version of the logo, upload it under Appearance → Customize → Site Identity and the badge can go.
- Our Impact charts read their colours from the --color-chart-* tokens and redraw when the theme changes (other scripts can listen for the "krm:themechange" event).

Header over the hero
- On pages that open with a photo or navy hero, the header is transparent with white text over it; after 80px of scrolling it becomes frosted glass. It turns solid while a menu is open. Pages without a hero (404, stories without a cover) keep the solid header.

Scroll progress bar
- A thin red-to-orange bar at the very top shows how far down the page the visitor is (under the admin bar when logged in). It is hidden on pages too short to scroll.

Scroll reveal
- Section headings, introductions and cards fade in and rise slightly when they scroll into view, once. Nothing on the first screen, no form and no donation card is animated; visitors who ask for reduced motion, and search engines, see everything at once.
- To animate a block you add yourself: in the block editor, Advanced → Additional CSS class(es): krm-reveal (the block) or krm-reveal-stagger (each item inside it, one after another). In HTML, the attributes data-reveal / data-reveal-stagger do the same. data-no-reveal turns it off for a block.

Photo bands
- Four sections show a photo through a see-through navy overlay: home "Flagship: Slavery & Freedom" and "Closing verse" (Pages → Home → Page content), About "Join the mission", and the Our Impact numbers strip (shown once impact numbers are set). Each has a "Background photo" field; empty = plain colour. The photo loads only when the section comes near the screen, and the theme uses its largest WebP copy of 250 KB or less. On desktops the photo stays still while the page scrolls (parallax); on phones and tablets, and with reduced motion, it scrolls normally.

== Speed ==

The theme already loads only what each page needs: one or two small stylesheets, scripts at the end of the page, the fonts (Cormorant Garamond headings, Figtree text, Newsreader italic for the top-bar verse) from Google Fonts in one request, shown with a fallback font until they arrive (display=swap), lazy-loaded images below the first screen, and a high-priority preload of each page's large hero image. Run Setup's image import (step 3 above): after it, images come from the site's own Media Library in the right size for each screen (phones get smaller files) instead of full-size files from the old site. Kingdom Revival → Settings → Images → "Image format" saves those resized copies as WebP (the default; much smaller files at the same visible quality). Images already uploaded keep their current copies until rebuilt with a plugin such as Regenerate Thumbnails. The home page's background video autoplays (muted) on every screen size and starts again from the beginning when it ends; only visitors with data saver on keep the background photo instead. The HTML carries no video link or poster: assets/js/front.js adds them once the page has finished loading, so the video never delays the first view (the photo, WebP with its JPG original as the poster fallback, shows until then). It pauses while scrolled out of view or while the tab is hidden and resumes after; a round pause / play button at the bottom left of the hero stops it (needed for accessibility, WCAG 2.2.2). If a browser refuses autoplay (e.g. iOS low-power mode), it starts on the visitor's first touch, scroll or key. The default is the ministry's own hero video, shipped with the theme: a 15-second loop, 1280px wide, no sound, as assets/video/hero.mp4 (H.264, about 2.2 MB) and assets/video/hero.webm (VP9, about 3.1 MB) (Pages → Home → Page content → "Background video (MP4 link)" and "WebM version"; they show as "krm-theme:video/hero.mp4" / ".webm"). A replacement should be similar: short, silent, under 4 MB. The photo viewer (assets/js/viewer.js) loads only on pages with photos that open full screen: home, About, ministry pages, stories, sermons and events. Design images are looked up in the Media Library in one go per page (two queries instead of two per image). Ministry gallery photos load as they scroll into view, in the size the photo grid shows. Cards and gallery tiles (home cause cards and field stories, story cards, Donate's impact cards, ministry and story galleries, What We Do) get 4:3 crops of portrait photos (sizes krm-card-480/800/1200, made only for photos taller than 5:4), so phones no longer download a whole tall photo to show its middle band; the crop shows exactly what the card showed. Images uploaded before theme 1.8.1 get these crops in the background, a few at a time on WP-Cron (option krm_card_backfill, -1 when done). Standard-density desktops up to 1536 px wide get the 1536 px copy of a hero or band photo when it is big enough to cover it; sharper screens keep the full image. Kingdom Revival → Settings → Images → "Unused plugin styles" leaves out WordPress editor styles and the Dashicons font that some plugins add to every public page (visitors only; on by default).
Most of a slow PageSpeed score usually comes from plugins, not the theme: page builders (Elementor, Elementor Pro, Header Footer Elementor), starter-template and form plugins load their CSS, fonts and jQuery on every page although the theme does not use them. Keep only the plugins the site needs (see GO-LIVE-CHECKLIST.md in the project).

On the hosting side (a theme cannot set these):
* Page caching: use the host's page cache, or one caching plugin (e.g. WP Super Cache, W3 Total Cache or LiteSpeed Cache on LiteSpeed servers). Pages are cache-safe: visitors' pages carry no per-visitor data.
* Compression and browser caching for theme files and uploads. Theme files have a version in their address (?ver=…) that changes with every theme update, so they can be cached for a year. On Apache/LiteSpeed hosts without a caching plugin that does this, add to .htaccess:
    <IfModule mod_deflate.c>
      AddOutputFilterByType DEFLATE text/html text/css application/javascript application/json image/svg+xml
    </IfModule>
    <IfModule mod_expires.c>
      ExpiresActive On
      ExpiresByType text/css "access plus 1 year"
      ExpiresByType application/javascript "access plus 1 year"
      ExpiresByType font/woff2 "access plus 1 year"
      ExpiresByType image/webp "access plus 1 year"
      ExpiresByType image/jpeg "access plus 1 year"
      ExpiresByType image/png "access plus 1 year"
      ExpiresByType video/mp4 "access plus 1 year"
    </IfModule>
* Optimisation plugins: they are not needed for the theme's own files. Avoid "delay JavaScript until interaction" options (the menus, donation form and gallery would not respond to the first tap) and extra lazy-loading of images or backgrounds (it would delay the hero image, which the theme loads first on purpose).

== Security and accessibility ==

* Forms (contact, partner, newsletter, prayer request) are protected without a captcha: a hidden "leave empty" field, a signed token from the page the form is on (it does not expire, so cached pages keep working), a minimum time on the form, at most 5 messages per visitor per 10 minutes, and messages with more than 3 links are kept as "possible spam" without an email. Logged-in users' posts also need a WordPress nonce. "Please reload the page and try again" means the token was missing — usually a page cached before a theme update; clear the page cache.
* Form Submissions hold visitors' personal details (prayer requests, donor details): only Administrators can see or export them. Donations: Editors and Administrators. Settings, Site text and Setup need an Administrator.
* Front-end pages send the headers X-Content-Type-Options, X-Frame-Options (SAMEORIGIN), Referrer-Policy and Permissions-Policy. If the host or a security plugin already sends them, remove the theme's with the `krm_security_headers` filter.
* Visitors can't look up user names (/?author=1 goes to the home page; the REST users list needs a login).
* Not done by the theme (use the host or one security plugin, e.g. Wordfence or Solid Security): login attempt limits, two-factor login, a firewall, XML-RPC blocking, file-change scans, backups.
* Accessibility: "Skip to content" link, keyboard-operable menus (Enter/Space opens, Esc closes), donation tabs (arrow keys), photo viewer and popups (focus stays inside, Esc closes, focus returns), visible focus outlines, labelled form fields whose errors are read out, alt text on every image (from the Media Library, or the alt field beside each image in Page content). When adding images, always fill in the Media Library "Alternative text"; leave it empty only for purely decorative images.

## Form emails (Phase 24)

**Since theme 1.18.2 form emails are sent by Web3Forms** (web3forms.com), not by the web host: Kingdom Revival →
Settings → Forms & newsletter → "Web3Forms access key" (set to the ministry's key by default). Web3Forms emails the
inbox the key was created for (Info@kingdomrevivalministries.com). This covers the Contact form, the four Partner With
Us forms, Prayer Request (and the home prayer form), Donate → "Let us know about your gift", the newsletter and the
testimony form. Every submission is still saved first under Form Submissions; the visitor's browser then sends the
email and the entry's "Email status" shows Sent / Failed (Web3Forms). If WordPress itself fails, the browser emails the
fields directly so nothing is lost. Without JavaScript the server forwards the email (Web3Forms' free plan may refuse
that; the entry then shows Failed). Free plan: 250 submissions a month. Empty the key to go back to WordPress sending
the emails itself (the SMTP notes below).

The Partner With Us sign-ups, Prayer Request (and the home page prayer form) and Donate → "Let us know about your gift" use one handler (inc/form-handler.php, assets/js/forms.js). Each submission is saved first under Kingdom Revival → Form Submissions (Administrators only; filter by form; the "Email status" column shows Sent / Failed / Not sent (possible spam)), then emailed as a branded HTML email with a plain-text copy. Reply-To is the visitor's email when they gave one; a WhatsApp number gets a "Message on WhatsApp" button. Dates are in Pakistan time (PKT). Private prayer requests have "PRIVATE" in the subject. The Donate email is a "Donation Intent" only, never a payment confirmation, and the form never asks for card or bank-login details (anything that looks like a card number or CVV typed in the message is removed).

Settings go in wp-config.php (above "That's all, stop editing!"), never in the theme:

```php
define( 'KRM_FORMS_TO_EMAIL', 'Info@kingdomrevivalministries.com' ); // recipients, comma separated (this is the default)
define( 'KRM_FORMS_FROM_EMAIL', 'no-reply@kingdomrevivalministries.com' ); // From address (default)
define( 'KRM_SMTP_HOST', 'mail.kingdomrevivalministries.com' ); // or smtp-relay.brevo.com, smtp.mailgun.org …
define( 'KRM_SMTP_PORT', 587 );          // 587 (TLS) or 465 (SSL)
define( 'KRM_SMTP_USER', 'no-reply@kingdomrevivalministries.com' );
define( 'KRM_SMTP_PASS', '…' );
// define( 'KRM_SMTP_SECURE', 'tls' );   // optional: 'tls', 'ssl' or ''
// define( 'KRM_SMTP_FROM', 'no-reply@kingdomrevivalministries.com' ); // if the SMTP account may only send as itself
```

Without KRM_SMTP_HOST WordPress sends with PHP mail(), which on shared hosting often lands in spam. Set up SPF and DKIM for the domain (and DMARC) for the sending service. For local testing, `define( 'KRM_MAIL_CAPTURE', true );` writes each email to wp-content/krm-mail/ (.eml, .html, .txt) instead of sending it (ignored on a "production" environment).

Spam protection: WordPress nonce (fetched fresh by the script, so cached pages work), hidden honeypot, at least 3 seconds on the form, at most 5 submissions per IP per 10 minutes, server-side validation. Without JavaScript the forms still post and the page shows the same messages. The success and error texts are editable in the page's "Page content" box ({name} = the visitor's first name).
* Photos and faces (theme 1.22.0): galleries (Gallery page, ministry pages, project pages) show every photo whole at its own shape in justified rows (.krm-just in theme-global.css, the shape from krm_ratio_style()). Other cropped photos are centred on their faces: inc/data/focal.php (built by tools/focal/build_focal.py in the project repo, OpenCV face detection, run on the theme images and an uploads folder) gives each photo a focus point, printed by krm_img_src() as data-focal and applied by assets/js/effects.js. Re-run the script after adding many new photos; without a focus point a photo keeps the template's crop.
